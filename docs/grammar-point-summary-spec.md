# 文法編 POINTまとめ 仕様書

## 1. 適用範囲

- 本仕様は文法編UnitのPOINTまとめ画面に適用する。
- Unit 1の具体例を含むが、Unit 2以降も同じ共通仕様を維持する。
- Unit 2以降では、表示レイアウトや共通CSSを変更せず、教材内容のみを差し替える原則とする。
- 本仕様に記載された共通仕様を変更する場合は、ユーザーの明示的承認が必要である。

## 2. 使用方針

- 本仕様の本文は要約ではなく、現行の確定版仕様をそのまま記録する。
- 勝手な仕様追加は行わない。
- 数値、色、フォントサイズ、太字、余白、カード構造、要素配置を省略しない。
- Unit 1固有内容と全Unit共通仕様を明確に分離する。
- Unit 2以降は共通仕様を変更せず、教材データを既存レイアウトへ流し込む。
- この仕様書は実装コードではなく、Markdown仕様書として管理する。

## 3. 共通仕様（全Unitで固定）

### 3.1 全体構造

- POINTまとめ画面は、上から順に次の構成とする。
  1. 見出し
  2. 主要ルール（メイン文）
  3. 2列対応表
  4. 3枚例文カード
  5. 次へボタン
- 1つのUnitで専用CSSを作らない。
- すべてのUnitは、共通POINTまとめCSSとUnitごとの教材データのみで表示する。
- Unitごとに専用のレイアウト・専用の色・専用の余白・専用のカード形状を作らない。

### 3.2 画面サイズ・幅

- PC表示では横幅を 1180px を上限とし、画面幅に応じて 100vw - 120px 以内で収まるようにする。
- 実装値: width: min(1180px, calc(100vw - 120px));
- max-width: 1180px;
- 画面幅を超えない。
- 横方向の構成は固定し、横幅の見た目を変える調整は行わない。

### 3.3 外側カード

- 外側のPOINTカードは、左右に13pxの余白を含めて広く見せる構成を維持する。
- 外側カードの幅は 1180px を超えない。
- 外側カードの padding は左右 42px、上下 34px とする。
- 実装値: padding: 34px 42px;
- 外側カードは text-align: left とし、中央寄せや右揃えにしない。
- 外側カードは justify-content: flex-start とし、縦方向に伸ばさない。
- 外側カードは height: auto とし、余白によりカードが縦に伸びることがないようにする。
- 外側カードは min-height: 0 とし、固定縦高を作らない。
- 外側カードには overflow: visible を維持する。
- 既存の大きな固定縦長化を避ける。

### 3.4 左揃え・テキスト配置

- 本画面のテキストは常に左揃えとする。
- 見出し、主要ルール、一覧、例文カードの本文はすべて左揃え。
- 中央寄せと右寄せを使わない。
- すべての本文は上から順に流れる構成とする。

### 3.5 見出し

- 見出しは 26px、太字 700、line-height 1.35、margin-bottom 32px。
- 実装値:
  - font-size: 26px;
  - font-weight: 700;
  - line-height: 1.35;
  - margin: 0 0 32px;
- 見出しの文字色は通常文字色と同じとする。
- 見出しは文法Unitの要点タイトルを表示する。

### 3.6 主要ルール

- 主要ルールは 20px、太字 700、line-height 1.6、margin-bottom 32px。
- 実装値:
  - font-size: 20px;
  - font-weight: 700;
  - line-height: 1.6;
  - margin: 0 0 32px;
- 主要ルールは 1文で表し、長くても一番重要な文をそのまま表示する。
- 主要ルール内で、意味づけの対象語は cyan 系の強調色を使う。
- 主要ルールの強調語は am / is / are を含む場合に cyan で表示する。
- 主要ルールはカード内の一番上の本文として扱う。

### 3.7 2列対応表

- 2列の対応表を持つ。
- grid-template-columns: repeat(2, minmax(0, 1fr));
- 列間の gap は 18px 14px。
- 表の下側余白は 18px。
- 各セルは 58px 以上の高さを持ち、padding 16px 20px、border 1px solid var(--border)、border-radius 10px を維持する。
- 各セルは flex で align-items: center を採用する。
- セル内の左側 key と右側 value は横並びとする。
- key と value はそれぞれ text-align: left。
- key は通常色、value は太字 600 で表示する。
- 例: I → am
- 右側の value が am / is / are のときは cyan 色で強調する。
- 矢印は → を使用し、白や薄い白で表示する。

### 3.8 例文カード群

- 例文群は 3列グリッドで表示する。
- grid-template-columns: repeat(3, minmax(0, 1fr));
- gap: 18px;
- margin-top: 28px;
- 各カードは min-height: 165px、padding: 20px、border: 1px solid var(--border)、border-radius: 12px を使用する。
- 各カードは flex-direction: column、align-items: stretch、justify-content: flex-start とする。
- 例文カードの各見出しラベルは、ラベルごとに色を変える。
  - 肯定文: cyan / 緑系の強調色で表示
  - 否定文: red 系の強調色で表示
  - 疑問文: blue 系の強調色で表示
- ラベルの左側には記号を置く。
  - 肯定文: ✓
  - 否定文: ×
  - 疑問文: ?
- 英文の本文は font-size: 22px、font-weight: 700、line-height: 1.45。
- 日本語説明は font-size: 16px、font-weight: 400、line-height: 1.5。
- 例文カードの本文は左揃え。

### 3.9 強調色

- 共通ルールとして、単語の強調色は以下の意味で利用する。
- cyan 系: am / is / are などの be動詞の基本形。これは「動詞の基本形」「現在形」「肯定の中心」として扱う。
- red 系: not、否定の変化、または否定のポイントを示す語。例は not、否定文の強調箇所を red にする。
- blue 系: 疑問文のラベルと疑問文の要点。例は Are、疑問文の見出し想起に使用する。
- 白/グレー系: 通常説明文、通常訳、通常の本文。
- red で全体を強調しない。否定や変化部分だけを red とする。
- cyan と red は、ポイントが「動詞の基本形」「否定」「疑問」を示す特に重要な語に限定して使う。

### 3.10 記号と表記

- 2列対応表では → を使用する。
- 例文のラベルでは ✓、×、? を使用する。
- 例文中の強調対象語は、単語そのものを span で包み、class を付けて扱う。
- 言語の右側に余計な装飾やアイコンを付けない。
- 主要ルールや例文中の記号は、通常の見出しよりも少し淡くしすぎない。

### 3.11 ボタン

- 次へボタンは、POINTまとめの最後に置く。
- ボタンは中央揃え。
- margin-top: 34px;
- margin-bottom: 34px;
- min-width: 260px;
- min-height: 56px;
- font-size: 18px;
- font-weight: 700;
- ボタンのウィンドウ内の配置は固定し、以後Unitでも同一に保つ。

### 3.12 高さ制御

- 共通で height を固定しない。
- min-height も固定しない。
- 伸縮する内容に応じて高さが自然に決まるようにする。
- 余白は gap・margin で制御し、固定高さで詰め込まない。
- 文字量が少ない場合でも、空白が大きく広がらないようにする。
- 例: height: auto; min-height: 0; を維持する。

## 4. Unit 1 固有仕様

### 4.1 Unit 1 の教材内容

- Unit 1 は be動詞 の基本を扱う。
- 主要ルール: "be動詞は am / is / are を使います。"
- 2列対応表の内容:
  - I → am
  - you → are
  - he / she / it → is
  - 複数 → are
- 例文 3件:
  1. 肯定文: "I am a student." / 「私は生徒です。」
  2. 否定文: "I am not a student." / 「be動詞の後ろに not」
  3. 疑問文: "Are you a student?" / 「be動詞を主語の前へ」
- 注意: 例文の強調対象語はそれぞれの本文に応じて設定する。
- 否定文の注記は "not" を red で強調する。
- 疑問文の注記は "Are" を blue で強調する。

### 4.2 Unit 1 の強調対象

- Unit 1 では am / is / are を cyan で強調する。
- Unit 1 では not を red で強調する。
- Unit 1 では Are を blue で強調する。
- これらの強調対象は共通仕様に沿ってグローバルに管理する。

### 4.3 Unit 1 の表示方針

- Unit 1 の内容は、共通POINTまとめの構造に教材データを流し込むだけで表示する。
- Unit 1 用の専用CSSを作らない。
- Unit 1 の見た目は共通仕様を満たす範囲で埋める。

## 7. 実装原則

### 7.1 Unitごとに専用CSSを作らない

- Unitごとの専用CSSを作成しない。
- 既存共通POINTまとめCSSを基準にし、教材データのみ差し替える。

### 7.2 教材内容と表示仕様を分離する

- 表示の仕様は共通部に固定する。
- 教材データは Unit 単位の本文データとして別管理する。
- 内容の差し替えは表示仕様に影響しない。

### 7.3 Unit 2以降は既存共通レイアウトへ教材データを流し込む

- Unit 2以降でも、共通のPOINTまとめひな形に教材内容のみを追加する。
- 既存の 1列 / 2列 / 3列 / 表 / 例文0〜3個 / 注意 / 補足 の構成で表現できる教材は、それを利用する。
- 新しいレイアウトや新しいCSSを追加するのは、例外的なケースのみとする。

## 8. 例外対応ルール

- 既存の構成で表現できない教材が出た場合のみ、新しい表示方法を検討する。
- その場合でも Unit 専用CSS は作らない。
- 共通性がある場合は、他Unitでも再利用できる新しい共通ブロックとして扱う。
- 共通仕様の拡張は、ユーザーの明示的承認がない限り行わない。

## 9. 実装・レビュー時の禁止事項

- 本仕様書を勝手に変更しない。
- Unit追加や問題追加の際に仕様書を自動修正しない。
- 仕様書とコードに差異がある場合、既存コードを正とせず仕様書を優先する。
- 実装者が仕様の解釈を変えて独自にレイアウトを増やさない。

## 10. 優先順位

POINTまとめについての優先順位は次の通りとする。

1. docs/grammar-point-summary-spec.md
2. 現在の共通POINTまとめ実装
3. Unit教材データ
4. 過去の旧CSS・旧実装

- 旧コードが仕様書と異なる場合、既存コードだから正しいとは判断しない。
- 仕様書が最優先であり、実装とデータはそれに従って整列する。

## 11. 仕様固定後の運用

- Unit 1 が仕様書どおりに表示されたら、POINTまとめ共通仕様を固定する。
- 以後は Unit追加のたびに横幅・文字サイズ・色・余白・カード形状・ボタン・共通CSSを再調整しない。
- Unit 2以降の作成は「何を教えるか」「何を表示するか」を中心に考える。
- 「何pxにするか」「カードを何色にするか」「どこへ置くか」を毎回再検討しない。
